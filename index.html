Inventory Anomaly Detection

Z-score statistical detection of sudden inventory fluctuations. Ranks anomalies by financial impact and surfaces items needing immediate procurement action.

inventory_anomaly_detection.sql 
WITH rolling_stats AS (
    SELECT
        sku_id, warehouse_id, transaction_date,
        daily_qty,
        AVG(daily_qty) OVER (
            PARTITION BY sku_id, warehouse_id
            ORDER BY transaction_date
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        )                    AS rolling_7d_avg,
        STDDEV(daily_qty) OVER (
            PARTITION BY sku_id, warehouse_id
            ORDER BY transaction_date
            ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
        )                    AS rolling_7d_stddev,
        LAG(daily_qty, 1) OVER (
            PARTITION BY sku_id, warehouse_id
            ORDER BY transaction_date
        )                    AS prior_day_qty
    FROM daily_inventory
),
anomaly_scoring AS (
    SELECT *,
        CASE
          WHEN rolling_7d_stddev = 0 OR rolling_7d_stddev IS NULL THEN 0
          ELSE ROUND(
            (daily_qty - rolling_7d_avg) / rolling_7d_stddev, 2
          )
        END                  AS z_score
    FROM rolling_stats
)
SELECT sku_id, anomaly_severity, z_score,
       estimated_variance_usd
FROM anomaly_flags
WHERE transaction_date = CURRENT_DATE
ORDER BY
    CASE anomaly_severity
      WHEN 'CRITICAL' THEN 1
      WHEN 'HIGH'     THEN 2
      WHEN 'MEDIUM'   THEN 3
    END, estimated_variance_usd DESC;

Supplier Performance Scorecard

Multi-dimensional scorecard tracking OTD, fill rate, invoice accuracy, and defect rate. Weighted composite score with quarter-over-quarter trend.

supplier_performance_analysis.sql 
-- Weighted composite score: OTD 35% | Fill 25%
-- | Invoice Accuracy 20% | Quality 20%
composite_score AS (
    SELECT
        d.supplier_id,
        s.supplier_name,
        d.on_time_delivery_pct,
        d.fill_rate_pct,
        i.avg_price_variance_pct,
        q.defect_rate_pct,
        cq.otd_pct_current_qtr
          - COALESCE(pq.otd_pct_prior_qtr,
                     cq.otd_pct_current_qtr) AS otd_qtr_delta,
        ROUND(
            (d.on_time_delivery_pct         * 0.35)
          + (d.fill_rate_pct               * 0.25)
          + (GREATEST(0, 100 - ABS(
               i.avg_price_variance_pct)*10) * 0.20)
          + (GREATEST(0, 100 - COALESCE(
               q.defect_rate_pct,0)*5)       * 0.20)
        , 1)                               AS composite_score
    FROM delivery_perf d
    JOIN procurement.suppliers s USING (supplier_id)
    LEFT JOIN invoice_accuracy i USING (supplier_id)
    LEFT JOIN quality_metrics  q USING (supplier_id)
    LEFT JOIN current_qtr     cq USING (supplier_id)
    LEFT JOIN prior_qtr       pq USING (supplier_id)
)

Multi-Source Financial Reconciliation

Reconciles AP invoices between WMS and ERP General Ledger. Classifies discrepancy types — missing in either system, amount mismatch, line count variance, tax variance — and generates an audit-ready exception report ranked by severity and financial exposure.

financial_reconciliation.sql 
-- FULL OUTER JOIN surfaces every discrepancy type in one pass
reconciled AS (
    SELECT
        COALESCE(w.invoice_number, e.invoice_number) AS invoice_number,
        COALESCE(w.vendor_id,      e.vendor_id)      AS vendor_id,
        w.wms_gross_amount,
        e.erp_gross_amount,
        CASE WHEN w.invoice_number IS NOT NULL THEN 1 ELSE 0 END AS in_wms,
        CASE WHEN e.invoice_number IS NOT NULL THEN 1 ELSE 0 END AS in_erp,
        COALESCE(e.erp_gross_amount, 0)
          - COALESCE(w.wms_gross_amount, 0)          AS gross_amount_variance
    FROM wms_invoices  w
    FULL OUTER JOIN erp_invoices e
        ON  w.invoice_number = e.invoice_number
        AND w.vendor_id      = e.vendor_id
),
classified AS (
    SELECT r.*,
        CASE
          WHEN in_wms=1 AND in_erp=0              THEN 'MISSING_IN_ERP'
          WHEN in_wms=0 AND in_erp=1              THEN 'MISSING_IN_WMS'
          WHEN ABS(gross_amount_variance) > 0.01  THEN 'AMOUNT_MISMATCH'
          WHEN line_count_variance != 0           THEN 'LINE_COUNT_MISMATCH'
          WHEN ABS(tax_variance) > 0.01           THEN 'TAX_VARIANCE'
          ELSE                                         'MATCHED'
        END AS discrepancy_type,
        CASE
          WHEN ABS(gross_amount_variance) >= 10000 THEN 'HIGH'
          WHEN ABS(gross_amount_variance) >= 1000  THEN 'MEDIUM'
          WHEN ABS(gross_amount_variance) > 0.01   THEN 'LOW'
          ELSE                                          'NONE'
        END AS variance_severity
    FROM reconciled r
    LEFT JOIN erp.vendors v ON r.vendor_id = v.vendor_id
)

ETL Pipeline — WMS to Snowflake

End-to-end incremental pipeline: SQL Server extract → pandas transform (type normalization, MD5 row hashing) → Snowflake bulk load via write_pandas. Watermark-driven incremental runs.

etl_pipeline.py 
def transform_inventory(df: pd.DataFrame) -> pd.DataFrame:
    df.columns = [c.upper() for c in df.columns]
    df["TRANSACTION_DATE"] = pd.to_datetime(
        df["TRANSACTION_DATE"], errors="coerce"
    )
    df["LOAD_TIMESTAMP"] = datetime.utcnow()

    # Drop bad records, log count
    before = len(df)
    df = df.dropna(subset=["QUANTITY", "TRANSACTION_DATE"])
    if (dropped := before - len(df)):
        log.warning(f"Dropped {dropped} rows with null values")

    # Signed quantity: shipments are negative
    df["SIGNED_QUANTITY"] = df.apply(
        lambda r: -abs(r["QUANTITY"])
            if r["TRANSACTION_TYPE"] in (
                "SHIPMENT", "ADJUSTMENT_NEGATIVE")
            else abs(r["QUANTITY"]),
        axis=1,
    )

    # Deterministic row hash for deduplication
    hash_cols = ["TRANSACTION_ID","SKU_ID",
                 "WAREHOUSE_ID","TRANSACTION_DATE","QUANTITY"]
    df["ROW_HASH"] = (
        df[hash_cols].astype(str)
        .agg("|".join, axis=1)
        .apply(lambda s: hashlib.md5(s.encode()).hexdigest())
    )
    return df

Automated Report Delivery

Data-driven system that executes scheduled SQL, formats styled Excel reports (alternating rows, freeze panes, auto-fit), and delivers via SMTP or SFTP. New reports added by config only.

automated_report_delivery.py 
def build_styled_excel(
    df: pd.DataFrame, config: ReportConfig
) -> bytes:
    output = io.BytesIO()
    with pd.ExcelWriter(output, engine="openpyxl") as writer:
        df.to_excel(writer, sheet_name=config.sheet_name,
                    index=False)
        ws = writer.sheets[config.sheet_name]

        # Dark navy header row
        header_fill = PatternFill(fill_type="solid",
                                  fgColor="1F3864")
        header_font = Font(color="FFFFFF", bold=True,
                           name="Calibri", size=11)
        for cell in ws[1]:
            cell.fill = header_fill
            cell.font = header_font
            cell.alignment = Alignment(
                horizontal="center", wrap_text=True)

        # Alternating row fill
        light_fill = PatternFill(fill_type="solid",
                                 fgColor="EEF2F7")
        for row_idx, row in enumerate(
            ws.iter_rows(min_row=2), start=2
        ):
            if row_idx % 2 == 0:
                for cell in row:
                    cell.fill = light_fill

        # Auto-fit column widths, freeze panes, auto-filter
        ws.freeze_panes = config.freeze_panes
        ws.auto_filter.ref = ws.dimensions
    output.seek(0)
    return output.read()

Data Quality Validation Framework

Rule-based engine for validating DataFrames — null checks, uniqueness, range bounds, referential integrity, regex patterns, and data freshness. CRITICAL failures block downstream pipeline steps. Ships with a factory-function rule API so new checks are one-liners, and exports a structured CSV quality report.

data_quality_framework.py 
# Define a rule suite with one line per check
rules = [
    row_count_threshold(min_rows=1,     severity=Severity.CRITICAL),
    not_null("transaction_id",          severity=Severity.CRITICAL),
    is_unique("transaction_id",         severity=Severity.CRITICAL),
    not_null("sku_id",                  severity=Severity.CRITICAL),
    in_range("quantity", 0, 100_000,    severity=Severity.HIGH),
    in_range("unit_cost", 0.01, 50_000, severity=Severity.MEDIUM),
    referential_integrity(
        "warehouse_id", VALID_WAREHOUSES, severity=Severity.HIGH),
    referential_integrity(
        "transaction_type", VALID_TXN_TYPES, severity=Severity.HIGH),
    freshness("transaction_date", max_age_hours=12,
              severity=Severity.HIGH),
]

validator = DataQualityValidator("WMS Inventory", rules)
report    = validator.run(df)
report.print_summary()

# Block the pipeline if any CRITICAL check failed
report.raise_on_critical()

Ecosystem Patterns & Best Practices

A reference file of production-grade Snowflake patterns used across pipeline and BI work — Time Travel, CDC with Streams & Tasks, Materialized Views, clustering, PII masking, and stored procedures.

Streams + Tasks (CDC)

Incremental MERGE into analytics fact table using Snowflake Streams to capture insert, update, and delete events, triggered every 15 min via a Task.

Time Travel

Point-in-time recovery with AT (OFFSET =>) and cross-time-period comparison to audit what changed between snapshots.

Materialized Views + Clustering

Pre-aggregated daily inventory summaries for BI query performance. Table clustering by date and warehouse eliminates full scans on date-filtered queries.

Dynamic Data Masking

Role-based PII masking on vendor contact fields using Snowflake masking policies — full value for authorized roles, redacted email domain for all others.

QUALIFY & FLATTEN

Window-function filtering with QUALIFY (avoids subquery overhead) and LATERAL FLATTEN for semi-structured JSON order lines.

Stored Procedure (JS)

Parameterized monthly close procedure that refreshes staging aggregates and upserts into the final finance close table atomically via MERGE.
